# 4 Реалізація підсистеми

## 4.1 Доменна модель

Реалізацію foundation-рівня почато з доменної моделі `src.domain`. У ній визначено
стабільні ідентифікатори жестів `GestureID`, перелік команд мобільного робота
`RobotCommand`, результат класифікації `GesturePrediction` та підтверджену подію команди
`CommandEvent`. Такий підхід зменшує ризик неузгодженості між класифікатором,
інтерпретатором команд, тестами та майбутнім датасетом.

## 4.2 Розпізнавання жестів

Захоплення кадрів реалізовано у модулі `src.capture.video_capture`. Модуль підтримує
два джерела даних: live-камеру та відеофайл для регресійного тестування. Для кожного
кадру виконується масштабування до робочої роздільної здатності, горизонтальне
віддзеркалення для природної взаємодії користувача та перетворення з колірного простору
BGR у RGB, необхідне для MediaPipe Hands.

Детектування руки винесено у `src.recognition.hand_detector`. Цей модуль ізолює залежність
від MediaPipe та повертає уніфікований результат: 21 ключову точку руки, тип руки
(`Left`, `Right` або `Unknown`) та оцінку впевненості. Завдяки цьому класифікатори не
залежать від внутрішнього формату MediaPipe.

Статичні жести реалізовано у `src.recognition.static_classifier`. Класифікатор працює з
21 ключовою точкою MediaPipe Hands та використовує геометричні ознаки: відстані між
суглобами, напрямок вектора пальця та відносний масштаб руки. Для динамічних жестів
реалізовано `TrajectoryBuffer`, який зберігає стислий опис останніх кадрів: центр долоні,
кінчик вказівного пальця, масштаб руки та час кадру.

Поточний `DynamicGestureClassifier` є baseline-рівнем для майбутнього порівняння з
LSTM-класифікатором. Він розпізнає три динамічні жести за траєкторією: горизонтальний
помах, круговий рух вказівним пальцем і рух руки до камери.

Для діагностики помилок розпізнавання додано модуль `src.recognition.gesture_pose`. Він
окремо від ML-класифікатора аналізує 21 точку MediaPipe Hands, визначає стани п'яти
пальців, напрямок великого та вказівного пальців, відстань між кінчиками великого і
вказівного пальців для `OK_SIGN`, а також містить очікувані шаблони пози для статичних
жестів. Це дає змогу порівнювати прогноз моделі з геометричними ознаками руки в кадрі.

Додатково реалізовано гібридний режим розпізнавання на основі `scikit-learn`. Модуль
`src.recognition.landmark_features` формує ознаки зі статичних MediaPipe-точок та з буфера
траєкторії, а `src.recognition.model_classifier` завантажує навчені `joblib`-моделі для
статичних і динамічних жестів. Такий підхід залишає rule-based класифікатори як baseline, але
дозволяє запускати прототип із моделями, навченими на контрольному наборі оператора. Для
навчання додано скрипт `scripts/train_gesture_models.py`; CLI, web UI та benchmark evaluator
підтримують параметри `--static-model` і `--dynamic-model`.

## 4.3 Адаптивне калібрування

Модуль адаптивного калібрування реалізовано у пакеті `src.calibration`. Він складається з
трьох основних частин:

- `LandmarkFeatureExtractor` формує нормований вектор ознак з 21 ключової точки руки;
- `CalibrationSession` накопичує зразки жестів і будує профіль користувача;
- `AdaptiveCalibrator` застосовує профіль для коригування результатів класифікації.

Профіль користувача зберігається у JSON-файлі та містить статистики для кожного
каліброваного жесту: кількість зразків, центроїд, стандартне відхилення та персональний
радіус прийняття. Для збору профілю додано скрипт `scripts/calibrate_user.py`, а основний
CLI підтримує запуск із готовим профілем через параметр `--calibration-profile`.

## 4.4 Інтерпретація та передача команд

Модуль `src.pipeline` поєднує всі компоненти в єдиний цикл обробки одного кадру:
детектування руки, статичну класифікацію, оновлення буфера траєкторії, динамічну
класифікацію, вибір фінального жесту та передачу результату в `CommandMapper`.

Модуль `CommandMapper` виконує debouncing: команда формується лише після стабільного
розпізнавання жесту протягом заданої кількості кадрів. Для аварійної зупинки використано
окремий поріг підтвердження, оскільки ця команда має підвищені вимоги до безпеки.
Додатково реалізовано `CommandConfirmationState`, який зберігає поточного кандидата
команди, кількість стабільних кадрів, необхідний поріг підтвердження та причину блокування.
Цей стан відокремлює етап "жест розпізнано" від етапу "команду передано роботу".

Передачу команд винесено в окремий пакет `src.transmission`. На цьому етапі реалізовано
`MockCommandSender` для тестів, `SerialCommandSender` для UART-зв'язку з мікроконтролером
та `RosCommandSender` для інтеграції з ROS.

## 4.5 Демонстраційний web-інтерфейс

Для демонстрації роботи прототипу реалізовано локальний web-інтерфейс `src.web_ui`.
Інтерфейс запускається без окремого frontend-build кроку та використовує стандартний
`http.server`, MJPEG-потік кадрів і JSON endpoints для стану pipeline.

На екрані відображаються відеопотік з overlay, поточний розпізнаний жест, confidence,
остання підтверджена команда, кандидат на підтвердження, прогрес debouncing, FPS, latency,
кількість знайдених рук, журнал команд, координати 21 landmark-точки та порівняння
фактичного стану пальців з очікуваним шаблоном вибраного жесту. Такий режим
підходить для захисту, оскільки дозволяє показати повний шлях "камера -> жест -> команда"
без підключення фізичного робота. Передавання команд у цьому режимі виконується через
`MockCommandSender`, а для апаратного тесту може бути обраний serial sender.

## 4.6 Висновок до розділу

Реалізований foundation-рівень перетворює тему дипломного проєкту з описової концепції
на тестовану програмну основу. Доданий механізм калібрування створює перший елемент
наукової новизни: персоналізоване коригування розпізнавання жестів перед формуванням
команди роботу.
