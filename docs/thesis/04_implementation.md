# 4 Реалізація підсистеми

## 4.1 Доменна модель

Реалізацію foundation-рівня почато з доменної моделі `src.domain`. У ній визначено
стабільні ідентифікатори жестів `GestureID`, перелік команд мобільного робота
`RobotCommand`, результат класифікації `GesturePrediction` та підтверджену подію команди
`CommandEvent`. Такий підхід зменшує ризик неузгодженості між класифікатором,
інтерпретатором команд, тестами та майбутнім датасетом.

## 4.2 Розпізнавання жестів

Статичні жести реалізовано у `src.recognition.static_classifier`. Класифікатор працює з
21 ключовою точкою MediaPipe Hands та використовує геометричні ознаки: відстані між
суглобами, напрямок вектора пальця та відносний масштаб руки. Для динамічних жестів
реалізовано `TrajectoryBuffer`, який зберігає стислий опис останніх кадрів: центр долоні,
кінчик вказівного пальця, масштаб руки та час кадру.

Поточний `DynamicGestureClassifier` є baseline-рівнем для майбутнього порівняння з
LSTM-класифікатором. Він розпізнає три динамічні жести за траєкторією: горизонтальний
помах, круговий рух вказівним пальцем і рух руки до камери.

## 4.3 Інтерпретація та передача команд

Модуль `CommandMapper` виконує debouncing: команда формується лише після стабільного
розпізнавання жесту протягом заданої кількості кадрів. Для аварійної зупинки використано
окремий поріг підтвердження, оскільки ця команда має підвищені вимоги до безпеки.

Передачу команд винесено в окремий пакет `src.transmission`. На цьому етапі реалізовано
`MockCommandSender` для тестів, `SerialCommandSender` для UART-зв'язку з мікроконтролером
та `RosCommandSender` для інтеграції з ROS.

## 4.4 Висновок до розділу

Реалізований foundation-рівень перетворює тему дипломного проєкту з описової концепції
на тестовану програмну основу. Наступним етапом є додавання калібрування користувача,
збір датасету та навчання класифікатора динамічних жестів.
