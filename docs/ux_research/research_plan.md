# План оцінювання користувацької взаємодії

## Мета

Метою оцінювання є перевірка того, чи є запропонований словник жестів зрозумілим,
ергономічним і придатним для швидкого керування мобільним роботом у прикладних сценаріях.

Оцінювання підтримує такі частини дипломної роботи:

- обґрунтування вибору жестів;
- формування функціональних і нефункціональних вимог;
- оцінювання UX-шару зворотного зв'язку;
- порівняння режиму без фідбеку та режиму з візуальним підтвердженням команди.

## Дослідницькі питання

RQ1. Які жести мають найвищу семантичну відповідність базовим командам мобільного робота?

RQ2. Які команди потребують додаткового підтвердження перед виконанням з погляду безпеки?

RQ3. Як візуальний фідбек впливає на прозорість стану системи під час керування жестами?

RQ4. Які жести викликають найбільше фізичне навантаження або втому руки?

RQ5. Які UX-ризики зменшує adaptive calibration перед формуванням команди?

## Гіпотези

H1. Жести з прямою семантичною відповідністю команді, наприклад відкрита долоня для
`STOP`, є кращими кандидатами для базового словника, ніж абстрактні жести.

H2. Візуальний фідбек має бути обов'язковим для команд руху, оскільки він показує різницю
між розпізнаним жестом і підтвердженою командою.

H3. Аварійні або незворотні команди, наприклад `EMERGENCY_STOP` і `CONFIRM_ACTION`,
потребують captive-фази підтвердження або підвищених порогів debouncing.

H4. Калібрування під користувача зменшує ризик помилкових команд, пов'язаних з різною
манерою виконання жестів.

## Матеріали

Для оцінювання використовуються:

- словник з 13 жестів;
- сценарії роботи мобільного робота;
- personas цільових користувачів;
- прототип pipeline з debug overlay;
- матриця UX-ризиків і вимог до безпеки.

## Методи

1. Аналіз сценаріїв використання.
2. Семантичне зіставлення жестів і команд.
3. Ергономічна оцінка складності виконання жестів.
4. Аналіз ризиків помилкового спрацювання.
5. Перевірка UX-рішень прототипу через debug overlay, debouncing і command log.
6. Підготовка протоколів для подальшої швидкої апробації.

## Метрики

| Метрика | Опис | Джерело |
|---|---|---|
| Semantic fit | Наскільки жест природно відповідає команді | аналітична матриця |
| Ergonomic load | Очікуване навантаження на кисть і пальці | аналітична матриця |
| Safety risk | Ризик небажаного виконання команди | аналіз сценаріїв |
| Feedback need | Потреба у візуальному підтвердженні | аналіз pipeline |
| Calibration need | Потреба в адаптивному профілі користувача | аналіз варіативності жестів |
| Command criticality | Наслідки помилкового спрацювання | аналіз команд робота |

## Етичні та практичні умови

- Аналітичне оцінювання не містить персональних даних.
- Протоколи інтерв'ю та usability test можна використати для подальшої апробації.
- Якщо буде виконано апробацію з людьми, результати слід зберігати окремо від
  аналітичних висновків.

## Очікуваний результат

Результатом оцінювання є обґрунтований словник жестів, список UX-вимог, перелік команд,
що потребують додаткового захисту, та рекомендації щодо debug overlay, debouncing і
адаптивного калібрування.
